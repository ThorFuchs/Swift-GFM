# Pinned cmark-gfm bundled test coverage

The Swift tests use the unmodified `test/` fixtures from github/cmark-gfm
revision `27d942c8b0a62d192f616e5bf3578f4b6a89e180`, version
`0.29.0.gfm.13`. They run as SwiftPM test resources, without a reference C
executable or network access. The fixture [README](../Tests/SwiftGFMTests/Fixtures/cmark-gfm/README.md)
records exact source hashes and licenses; `.gitattributes` protects bytes such
as intentional CR characters and a NUL. This is the repository-bundled corpus,
not the independently published 677-example GFM web specification or the
newer standalone cmark 0.31.2 suite.

In addition, a derived, reproducibly checked fixture tests the exact HTML for
all 2,125 named entities listed in the pinned backend's `entities.inc`. Its
expected outputs were generated by an independently built pinned C executable;
the original upstream entity data remains unchanged in the vendor directory.

| Upstream file | Source examples | Direct byte comparisons | Explicit skips |
| --- | ---: | ---: | --- |
| `spec.txt` | 672 | 670 | 2 source-disabled |
| `extensions.txt` | 30 | 29 | 1 `<IGNORE>` expected output |
| `regression.txt` | 26 | 26 | 0 |
| `smart_punct.txt` | 16 | 16 | 0 |
| `extensions-full-info-string.txt` | 4 | 4 | 0 |
| `extensions-table-prefer-style-attributes.txt` | 1 | 1 | 0 |
| Total | 749 | 746 | 3 |

Tests retain example numbers and execute the per-example extensions and
suite-specific options from the upstream CMake test configuration. The
`extensions` and table-style tests also enable footnotes. All comparisons use
the upstream unsafe-HTML test mode. Unlike upstream's `--no-normalize` runner,
which still converts CRLF to LF, the direct Swift assertions compare exact
UTF-8 output bytes. The two source-disabled cases are 279 and 280. The skipped
case is `extensions#20`, for which the original expected text is `<IGNORE>`;
it has no expected HTML to assert. It is nevertheless included in the separate
six-format C-backend differential check.

The upstream `spec_tests.py --no-normalize` runner was independently run
against the SwiftGFM CLI on Linux: spec 670/670, extensions 30/30, regression
26/26, and smart punctuation 16/16. Its extension count includes the
`<IGNORE>` case as a pass without comparing HTML, and its spec count omits the
two disabled examples entirely. The Swift tests report those three separately.

## CommonMark round trips

The test target checks 704 non-skipped examples from the bundled spec,
extensions, and option suites by rendering to CommonMark and then HTML. As the
upstream runner does, it removes the writer's synthetic `<!-- end list -->`
comment. For 699 cases the final HTML matches the original expected bytes.

Five spec examples produce different exact HTML after the pinned C backend's
round trip. The tests assert the independently captured C output for these
five, and separately assert that it differs from the original fixture output.
They do not silently rewrite the official fixtures or count these as exact
round-trip matches to those fixtures:

| Example | Fixture output | Pinned backend round-trip output |
| ---: | --- | --- |
| 51, 52 | A newline inside heading emphasis | A space in that position |
| 65 | A newline in the heading | A space in that position |
| 108 | One space inside inline code | Three spaces inside inline code |
| 344 | Two spaces in the second inline code node | Four spaces in that node |

The last two alter literal code text. The upstream round-trip runner normally
uses its HTML normalizer, which collapses those whitespace differences; they
must not be described as byte-identical or universally semantically equivalent.
The direct source-to-HTML examples still match their fixture bytes.

## Reference and documentation checks

`Tools/check_bundled_cmark_reference.py` runs every source-enabled input,
including the `<IGNORE>` case, through both SwiftGFM's CLI and an independently
built pinned C executable for all six output formats. It compares raw bytes and
reports the exact input, commands, statuses, and base64 outputs for failures.
The executable's hash is recorded; verify the reference checkout revision
independently. This is backend parity, not formal specification certification.
On Linux this comparison matched 4,482/4,482 outputs: 747 enabled inputs across
six formats, with the two source-disabled specification cases excluded.

The independent pinned upstream extractor was also checked against the local
fixture extraction for all 747 enabled inputs and their section names, example
numbers, Markdown, expected HTML, and extension labels. The Swift tests read
the original fixture bytes directly and retain the original example numbers.

The upstream pathological test script was also run against SwiftGFM's CLI on
Linux: 21 passed, zero errored, zero ignored. It checks large or adversarial
inputs under upstream's per-test timeouts; a pass does not establish hard
resource limits or safety for all inputs. Reproduce it after checking out the
pinned upstream revision with:

```sh
python3 .references/cmark-gfm/test/pathological_tests.py --program "$PWD/.build/debug/swift-gfm html"
```

Run `swift test`, `python3 -m unittest discover -s Tools -p 'test_*.py'`, and
`sh Tools/build-docc.sh`. The DocC script extracts the public symbol graph,
checks source-declared symbol documentation, and treats DocC warnings as
errors. CI also runs strict `swift-format` lint, release tests, and Linux thread
and address sanitizer tests. Leak detection is disabled for the address
sanitizer run; it is not a leak check. See [REPRODUCTION.md](REPRODUCTION.md)
for reference-build commands.
