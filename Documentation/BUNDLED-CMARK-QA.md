# Pinned cmark-gfm bundled test coverage

The Swift tests use four unmodified `test/` fixtures from github/cmark-gfm
revision `27d942c8b0a62d192f616e5bf3578f4b6a89e180`, version
`0.29.0.gfm.13`. They run as SwiftPM test resources without a reference C
executable or network access. The fixture [README](../Tests/SwiftGFMTests/Fixtures/cmark-gfm/README.md)
records their exact hashes, licenses, and the provenance of two removed files.
This corpus is not the independently published GFM web specification.

In addition, a derived, reproducibly checked fixture tests the exact HTML for
all 2,125 named entities listed in the pinned backend's `entities.inc`. Its
expected outputs were generated by an independently built pinned C executable;
the vendored upstream entity data remains unchanged.

| Upstream file | Source examples | Direct byte comparisons | Explicit skips |
| --- | ---: | ---: | --- |
| `spec.txt` | 672 | 670 | 2 source-disabled |
| `extensions.txt` | 30 | 29 | 1 `<IGNORE>` expected output |
| `extensions-full-info-string.txt` | 4 | 4 | 0 |
| `extensions-table-prefer-style-attributes.txt` | 1 | 1 | 0 |
| Total | 707 | 704 | 3 |

Tests retain example numbers and execute the per-example extensions and
suite-specific options from the upstream CMake configuration. The `extensions`
and table-style suites also enable footnotes. All comparisons use the upstream
unsafe-HTML test mode. Unlike upstream's `--no-normalize` runner, which still
converts CRLF to LF, the direct Swift assertions compare exact UTF-8 output
bytes. The two source-disabled cases are 279 and 280. The skipped case is
`extensions#20`, whose expected text is `<IGNORE>`; it has no expected HTML to
assert, but its input is included in the six-format backend comparison.

The previously bundled `regression.txt` and `smart_punct.txt` (26 and 16 cases)
were removed from new source snapshots because their individual provenance
remains unresolved. They remain in earlier history and the published 1.0.0
source tag. Thirteen separately authored neutral cases exercise selected
behavior, including smart punctuation, links and GFM extensions. These cases
are not a complete replacement for the 42 removed upstream cases. With a
separately built pinned C reference, their output is also compared independently;
when the reference is not configured that comparison is explicitly skipped.

CI additionally runs the upstream `spec_tests.py --no-normalize` runner against
the CLI using the separate pinned upstream checkout. It runs the 26 regression
and 16 smart-punctuation cases there as separate checks; they are not bundled
fixtures. Acquiring the files separately does not determine the rights for their
use. The upstream runner reports the extension `<IGNORE>` case as a pass without
comparing HTML; it must not be counted as an expected-output comparison.

## CommonMark round trips

The test target checks 704 non-skipped examples from the bundled spec,
extensions, and option suites by rendering to CommonMark and then HTML. As the
upstream runner does, it removes the writer's synthetic `<!-- end list -->`
comment. For 699 cases the final HTML matches the original expected bytes.

Five spec examples produce different exact HTML after the pinned C backend's
round trip. The tests assert the independently captured C output for these
five, and separately assert that it differs from the original fixture output.
They do not silently rewrite the official fixtures or count these as exact
round-trip matches to those fixtures:

| Example | Fixture output | Pinned backend round-trip output |
| ---: | --- | --- |
| 51, 52 | A newline inside heading emphasis | A space in that position |
| 65 | A newline in the heading | A space in that position |
| 108 | One space inside inline code | Three spaces inside inline code |
| 344 | Two spaces in the second inline code node | Four spaces in that node |

The last two alter literal code text. The upstream round-trip runner normally
uses its HTML normalizer, which collapses those whitespace differences; they
must not be described as byte-identical or universally semantically equivalent.
The direct source-to-HTML examples still match their fixture bytes.

## Reference and documentation checks

`Tools/check_bundled_cmark_reference.py` runs every source-enabled bundled input,
including the `<IGNORE>` case, through both SwiftGFM's CLI and an independently
built pinned C executable for all six formats. It compares raw bytes and
reports exact inputs, commands, statuses, and base64 outputs for failures. The
executable's hash is recorded, but its source revision must be verified
independently. The expected inventory is 4,230 comparisons: 705 enabled inputs
across six formats, with two source-disabled cases excluded. This is backend
parity, not formal specification certification. A failed or unavailable
reference is not a pass.

The pinned upstream extractor is also checked against the local fixture
extraction for 705 enabled inputs, including the `<IGNORE>` input. It compares
section names, example numbers, Markdown, expected HTML, and extension labels.

CI also runs upstream's pathological test script against the SwiftGFM CLI
(21 tests). It checks large or adversarial inputs under upstream's per-test
timeouts; a pass does not establish hard resource limits or safety for all
inputs. Reproduce it after checking out the pinned upstream revision with:

```sh
python3 .references/cmark-gfm/test/pathological_tests.py --program "$PWD/.build/debug/swift-gfm html"
```

Run `swift test`, `python3 -m unittest discover -s Tools -p 'test_*.py'`, and
`sh Tools/build-docc.sh`. CI also runs strict `swift-format` lint, release tests,
and Linux thread and address sanitizer tests. Address Sanitizer's leak
detection is disabled, so it is not a leak check. See [TESTING.md](TESTING.md).
