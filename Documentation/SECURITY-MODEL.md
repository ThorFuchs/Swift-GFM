# Security model

The C library's default HTML policy filters raw HTML and some unsafe links. `.allowUnsafeHTML` enables the backend's `CMARK_OPT_UNSAFE`; neither setting is a complete HTML sanitizer or a reproduction of GitHub.com hosted post-processing. Hosts must apply context-appropriate output policies.

The parser is native C in the application process. Parsing and rendering through `MarkdownEngine` are serialized with a shared lock to protect this C revision's process-global mutable state; code calling the C target directly bypasses that lock. Optional [resource limits](RESOURCE-LIMITS.md) can reject input before parsing and stop Swift AST projection after a node or depth threshold. Limits default to unlimited. They do **not** impose hard bounds on C allocation, output size, execution time, or running-task cancellation; cmark has already parsed the input before AST projection begins. The C default allocator may abort the process on allocation failure. XML output includes a DTD declaration, so consumers must configure their XML parser's external-entity behavior. See [CMARK-CONCURRENCY.md](CMARK-CONCURRENCY.md) for the design and [WRAPPER-API.md](WRAPPER-API.md) for current qualification.
